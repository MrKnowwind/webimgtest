封面经验目标：在你的目标设备和网络下，未缓存单张从请求到可显示尽量 ≤ 500 ms；500–1000 ms 可继续优化，超过 1 s 优先排查。这是本工具的经验建议，不是通用标准。

体积起点：约 150 × 200 CSS px 的封面可先尝试 30–100 KB 的 WebP / AVIF，并准备与目标 DPR 匹配的像素；细节丰富的封面仍要以肉眼对比为准。多张同时加载时还需要控制首屏总量。

整页体验：Google 的 LCP 良好标准是 ≤ 2.5 s（75% 访问），它衡量整页最大内容绘制，与这里的单图计时不同。

可靠测试：F12 → Network → Disable cache → 选择 Fast 4G / Slow 4G 等目标网络 → 重测 URL 图片。冷缓存和热缓存各测 3–5 次，并在真实手机上复核。手机预览只改布局，不模拟 CPU 或设备 DPR。

COVER LAB / 把每一个像素用在恰好的地方。临时预览 · 无账号 · 无服务端存储

用 F12，看清每一个细节

  1. 看实际尺寸

    右键大厅封面 → 检查。鼠标悬停 <img>，查看 Rendered size、Intrinsic size 和文件地址。Elements 的 Computed 可检查宽高与 object-fit。

  2. 测真实加载

    添加线上图片 URL（也支持本站相对路径），在 Network 勾选 Disable cache、选好限速，点击“重新测试”。使用 Img 过滤请求，查看 Size、Time 和 Timing。自动计时包含加载及解码，缓存状态以 Network 为准。

  3. 测试自己的图片网络下载

    把图片提交到仓库 public/test-images/ 并等待自动部署，再在 URL 输入框填写 ./test-images/文件名.webp。临时上传生成的是 blob: 地址，没有服务器下载过程。

  4. 判断清晰度

    在原图查看器中切换 1:1 / 适应，结合大厅实际效果比较。DPR 检测项只是计算要求；真实设备模拟请用 F12 设备工具栏并设置 DPR。
